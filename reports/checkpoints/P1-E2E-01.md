# P1-E2E-01 — Reproducibility trong môi trường cô lập an toàn

## Stage này giải quyết vấn đề gì?

Kiểm tra rằng dependency và artifact không chỉ tình cờ chạy nhờ virtual environment cũ của máy. **Reproducibility** là người khác làm lại được với prerequisite đã ghi, giống làm món ăn từ công thức thay vì dựa vào nguyên liệu bí mật đang có sẵn trong bếp.

## Trước stage này project thiếu gì?

Đã có runtime evidence trên `.venv` hiện hành và Airflow container, nhưng chưa có xác nhận rằng host dependency manifest đủ để dựng một environment mới và reload ML artifact.

## Agent đã sửa những file nào?

- `requirements.txt` không cần thay đổi: được dùng như declared source of truth.
- Checkpoint này ghi evidence; không sửa `data/raw/**`, SQL volume hay artifact.

## Runtime evidence là gì?

Một virtual environment mới, tách khỏi repo `.venv`, được tạo tại temporary OS path. `pip install -r requirements.txt` hoàn tất với pin declared; import `numpy`, `pandas`, `pyodbc`, `scikit-learn`, `joblib` PASS. Kết quả artifact reload:

```text
IMPORT_PASS
SKLEARN=1.7.2
ARTIFACT=Pipeline
```

`docker compose --profile orchestration config` và Airflow image/runtime đã được validate ở các stage orchestration. Re-run SUSEP loader trong Airflow container trả:

```text
[SKIPPED] batch=0EDEB285-DB67-4159-A6D5-FE85F00F085A;
source_rows=8338214; accepted=8338214; rejected=0
```

Điều đó tái xác nhận idempotency, không reread/insert 8,3 triệu row vào canonical staging.

## Data/code đi qua đâu?

Environment mới chỉ cài dependency host và load artifact read-only. Docker Compose cung cấp SQL Server/Airflow boundary; raw được mount read-only. Không reset database volume hoặc reload full raw vì một “fresh test” không được phép phá evidence runtime đang có.

## Owner cần hiểu khái niệm gì?

- **Pinned dependency:** khóa version như scikit-learn 1.7.2 để file model không hỏng do library mới hơn.
- **Isolated virtual environment:** hộp dụng cụ mới, không dùng package vô tình còn trên máy.
- **Idempotent rerun:** chạy lại source cũ nhận `SKIPPED`, không phát sinh fact mới.

## Owner chưa cần học gì?

Chưa cần dựng CI/CD hay publish image registry. Mục tiêu là kiểm tra local setup có thể tái lập theo manifest.

## Owner tự kiểm tra thế nào?

```powershell
python -m venv <thu-muc-tam>
<thu-muc-tam>\Scripts\python.exe -m pip install -r requirements.txt
<thu-muc-tam>\Scripts\python.exe -c "import joblib; print(type(joblib.load('ml/artifacts/claim_risk_model_v001.joblib')).__name__)"
docker compose --profile orchestration config
```

## Điều gì có thể nhìn đúng nhưng thực ra sai?

File `.joblib` tồn tại không đảm bảo reload được: global Python từng có scikit-learn khác version. Và isolated host dependency test không phải lời tuyên bố đã reset/rebuild full 8,3-million-row database; reset đó không an toàn trong environment chứa evidence. Prerequisite và migration order phải đọc từ run guide trước khi dựng instance mới.

## Stage verdict

**PASS trong phạm vi fresh/isolated an toàn.** Host dependencies và artifact reload tái lập được; Docker/Airflow runtime đã có evidence riêng. Full destructive database replay cố ý không chạy trên instance evidence hiện hữu.
